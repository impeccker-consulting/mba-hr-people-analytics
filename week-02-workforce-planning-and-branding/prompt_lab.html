Shiny in 6 steps: what each function does

A Shiny app is two halves that talk through IDs. Hover any function name for a one-line meaning.

input$ : what the user choseinput$ax holds the dropdown value. Change it and the server reruns.

1Foundations

Load the toolbox and write small helper functions before the app exists.

library()install.packages()function()read_csv()

2UI: the screen

Describe what the user sees: pages, menus, boxes, sliders and empty slots for charts.

dashboardPage()menuItem()fluidRow()sliderInput()plotOutput()

3Server A: data and first tabs

Read the files, clean them, then fill the chart slots for tabs 1 to 5.

server()reactive()input$xrenderPlot()withProgress()

4Server B: models and what-ifs

Train the attrition models and let sliders re-run the maths for tabs 6 to 8.

renderDT()renderValueBox()renderPlotly()glm()ranger()

5Server C: text, jobs and the plan

Emoji, job-ad and brand-prescription tabs, then close the server and start the app.

renderUI()sprintf()shinyApp()

6Audit

Check that every slot in the UI has a matching output in the server, then run it.

output$xrunApp()setdiff()
Golden rule: the ID in the UI and the ID in the server must match exactly. plotOutput("heat") in the UI needs output$heat in the server. Most Shiny errors come from a mismatch.
